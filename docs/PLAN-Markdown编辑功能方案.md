## 0. 结论摘要

1. **建议定位**：从「只读阅读器」演进为「**阅读优先、本地轻编辑**」，而不是转型为知识库 / 笔记 / 多文件编辑器。编辑能力默认入口不打扰阅读主流程，仍保持零权限、纯离线、零追踪。
2. **一期建议范围**：源码编辑、格式化工具栏、保存 / 另存为、新建 Markdown、同页预览、未保存离开保护、编码与换行保持、应用内草稿兜底。
3. **技术路线**：新增独立 `EditorActivity`；复用现有 `MarkdownParser → RenderPipeline → ReaderAdapter` 做预览；新增 `DocumentTextCodec` / `DocumentWriter` / `DraftStore`；不引入任何第三方编辑库、WebView 或新权限。
4. **安全底线**：只通过 SAF 对用户显式选择的单个文件进行读写；`uses-permission` 仍为 0，无网络代码路径；APK 体积红线与现有 CI 不变。
5. **审核结论**：全部决策已于 2026-09-11 批准，详见 §10；一期按 v1.1.0（versionCode 10100）实施，表格/图片插入移入二期。

## 1. 背景与主要矛盾

### 1.1 现状

- 当前 App 是纯阅读器：`MainActivity + ReaderActivity`，SAF 读取 `content://` / `file://`，解析后 RecyclerView 渲染。
- `PRD §1.1` 明确定位「只做阅读」；`PRD §4.2` 明确不做「编辑功能（任何文本修改能力）」。
- 当前依赖白名单和 CI 红线：0 权限、0 网络、release arm64 目标 ≤ 6MB。
- 现有代码只读不写：`DocumentLoader` 负责字节读取和解码；没有任何 `OutputStream` 写文件路径。

### 1.2 加编辑后需要正面回答的矛盾

| 矛盾 | 说明 | 本方案建议 |
| --- | --- | --- |
| 产品定位冲突 | PRD 明确把编辑列为非目标 | 定位改为「阅读优先的本地轻编辑」；编辑是次级能力，不做完整笔记软件 |
| 隐私叙事 | SAF 写权限是否需要申请系统权限？ | 不需要。读写均来自用户对单个文件的 SAF 显式授权，manifest 权限仍为 0 |
| 数据安全 | Android SAF 没有可靠的「原子替换」语义 | 覆盖保存前在应用私有目录保留草稿 / 快照，失败不静默丢数据；提供另存为 |
| 体积红线 | 最新编辑器库通常很大 | 不引第三方编辑库；用原生 `EditText`，预计增量 < 200KB |
| 性能边界 | `EditText` 不适合 20MB 级文档 | 一期限制可编辑大小（建议 ≤ 1MB），超出只读并提示；阅读侧 20MB 上限不变 |
| 编码一致 | 现有解码支持 GB18030 等，但写回若默认 UTF-8 会改变文件 | 新增编码保持策略：优先按原编码、原换行、原 BOM 写回；无法保持时强制另存为 |

## 2. 产品定位与范围

### 2.1 建议定位

> **墨阅 · 阅读优先的本地 Markdown 轻编辑**
>
> 先把「打开即读」保持得足够快、足够干净；需要改字时，提供顺手、可控、不联网、不申请权限的源码编辑与预览。

对外文案建议保留「零权限、纯离线、零追踪」，同时把「轻编辑」作为显式能力写在功能列表，避免原「只读」承诺被用户认为被破坏。

### 2.2 一期目标（P0）

| 编号 | 能力 | 说明 |
| --- | --- | --- |
| F-14 | 进入编辑 | 阅读页顶栏新增「编辑」入口；只读 URI 引导重新授权或另存为；超大 / 编码不确定文档有明确兜底 |
| F-15 | 源码编辑 | 多行纯文本编辑、选区、IME、光标、撤销能力沿用系统文本编辑；Markdown 源码即所见 |
| F-16 | 格式工具 | 粗体、斜体、标题、引用、无序列表、有序列表、行内代码、围栏代码、链接、分割线的选区 / 行级快捷操作 |
| F-17 | 保存 / 另存为 | 覆盖回原文件；另存为走 `ACTION_CREATE_DOCUMENT`；失败保留草稿并明确提示 |
| F-18 | 新建 Markdown | 首页新增「新建」入口；先建立内存缓冲，首次保存时选择位置，避免留下空文件 |
| F-19 | 同页预览 | 编辑页内切换「编辑 / 预览」；预览复用现有原生渲染管线，不做实时分屏 |
| F-20 | 离开保护 | 有未保存修改时返回拦截：保存 / 放弃 / 取消 |
| F-21 | 编码与换行保持 | 保留原 UTF-8 / BOM / UTF-16 / GB18030 编码与 LF / CRLF 换行；不可表示字符明确提示 |
| F-22 | 草稿兜底 | 编辑草稿存应用私有目录；崩溃、进程被杀、保存失败后可恢复；成功保存后清理 |

### 2.3 二期候选（P1）

- 查找 / 替换；
- 撤销 / 重做按钮（一期先沿用系统 undo 能力）；
- 表格片段、图片相对路径插入；
- 外部文件被其他 App 修改的冲突检测；
- 平板横屏分栏编辑 / 预览；编辑入口草稿标记；
- 编辑字号 / 行距设置。

### 2.4 明确不做（防范围蔓延）

- 富文本 / WYSIWYG `contenteditable` / 隐藏 Markdown 语法的「伪渲染编辑」；
- 云同步、账号、协作、版本历史、Git；
- 多文件管理、文件树、多标签、跨目录搜索；
- 在线图床、网络图片、任何网络能力；
- 第三方编辑器库、WebView 预览方案；
- 自动改写原文件格式（自动格式化、自动排版、自动转换编码）。

## 3. 核心交互设计

### 3.1 信息架构变化

```
首页
├── 打开文件
├── 新建 Markdown        ← 新增
└── 最近文件

阅读页
├── 正文渲染区
├── 大纲抽屉
├── 底部工具条（大纲 / 主题 / 字号 / 搜索）
└── 顶栏「编辑」          ← 新增

编辑页（新增）
├── 顶栏：返回 / 文件名 / 未保存标记 / 预览切换 / 保存 / 更多（另存为）
├── 编辑区：全屏 EditText（等宽、主题联动）
├── 预览区：复用 ReaderAdapter 的原生渲染
└── 底栏：Markdown 格式工具条
```

### 3.2 流程一：编辑已有文件

```
阅读页 → 点「编辑」
  ├─ 文档 ≤ 编辑上限 且 URI 已有写权限
  │     → 直接进入编辑页
  ├─ URI 只有读权限/不可写
  │     → 弹窗：重新授权 / 另存为 / 取消
  │         ├─ 重新授权：ACTION_OPEN_DOCUMENT（READ|WRITE，定位当前文件）
  │         │     用户选择后持久化读写授权；若选的是同一文件则继续编辑
  │         └─ 另存为：进入编辑页，首次保存时 ACTION_CREATE_DOCUMENT
  └─ 超过编辑上限 / 编码不可靠
        → 提示后保持只读（编码不可靠时允许另存为，不允许覆盖原文件）
```

### 3.3 流程二：新建 Markdown

```
首页 → 新建 Markdown
  → 编辑页（内存缓冲，标题「未命名.md」）
  → 用户输入内容
  → 点「保存」
      → ACTION_CREATE_DOCUMENT(text/markdown, 建议名 未命名.md)
      → 写入内容 → 切换当前会话到新 URI → 更新最近列表
```

建议采用「先编辑、首次保存再选位置」的方式：用户放弃时不会产生空文件；同时保证没有写权限时也能开始输入。

### 3.4 流程三：保存后回阅读页

```
编辑页保存成功 → setResult(SAVED_URI/IP)
  → 若由阅读页进入：阅读页收到结果后重新加载文件，避免继续显示旧内容
  → 若为「另存为」：阅读页切换到新 URI
  → 最近列表在下一次 onResume 刷新
```

阅读页重载时，编辑器打开前会触发 `onPause` 保存阅读进度，因此重载后可恢复大致位置。

### 3.5 编辑页关键交互

| 场景 | 规范 |
| --- | --- |
| 进入编辑 | 默认聚焦文首或上次光标；打开编辑页耗时目标 ≤ 800ms（500KB 文档） |
| 格式工具 | 作用于当前选区；无选区时插入占位文本并选中占位符，方便直接输入 |
| 标题 / 列表 / 引用 | 行级前缀；选中多行时逐行处理，再次点击可切换取消 |
| 链接 | 选中文字时包成 `[文字](光标)`；无选区时插入 `[链接文字](url)` 并选中提示文字 |
| 预览切换 | 保留编辑态光标和滚动位置；预览从顶部开始；输入后切预览以 300ms 防抖重新解析 |
| 保存中 | 顶栏保存按钮禁用 + 进度；完成后 Toast / 返回 |
| 返回 | 有修改则弹「保存 / 放弃 / 取消」；保存失败不关闭页面 |
| 切后台 | 保存编辑草稿到应用私有目录，不回写原文件 |
| 输入法 | 底栏格式工具应能随 IME 上移；编辑区 `adjustResize`，避免键盘遮挡 |

## 4. 技术方案

### 4.1 模块划分

```
EditorActivity
├── EditorSession              // 当前文档 URI、名称、内存文本、编码元数据、dirty 状态
├── MarkdownEditCommands       // 纯函数：选区格式操作 → 新文本 + 新选区（可 JVM 单测）
├── DocumentTextCodec          // 字节 ↔ 文本，编码 / BOM / 换行检测与保持
├── DocumentWriter             // 覆盖保存 / 另存为 / file:// 兜底 / 写入失败处理
├── DraftStore                 // 应用私有目录草稿快照、恢复、清理
├── EditorPreviewController    // 复用 MarkdownParser + RenderPipeline + ReaderAdapter
└── EditorToolbar              // 格式按钮与快捷键命令映射
```

尽量不修改现有阅读链路：阅读侧仍只读加载，编辑侧独立 Activity。

### 4.2 打开与写权限

- 阅读入口保持现状：`OpenDocument` + 只读 `takePersistableUriPermission`。
- 进入编辑前检查：
  - `DocumentFile.fromSingleUri(...).canWrite()`；
  - `context.checkUriPermission(uri, Process.myPid(), Process.myUid(), FLAG_GRANT_WRITE_URI_PERMISSION)`。
- 只读 URI 的重新授权建议使用自定义 `Intent`（而不是默认 `OpenDocument` contract），显式带：
  - `ACTION_OPEN_DOCUMENT`
  - `CATEGORY_OPENABLE`
  - `FLAG_GRANT_READ_URI_PERMISSION or FLAG_GRANT_WRITE_URI_PERMISSION`
  - `EXTRA_INITIAL_URI = 当前 URI`（API 26 可用，最小 SDK 26，满足）
  - 成功后 `takePersistableUriPermission(..., READ | WRITE)`，并更新 `RecentStore`。
- `file://`：
  - 若 `File.canWrite()` 为 true，可直接 `FileOutputStream`；
  - Android 10+ 分区存储下多数共享路径不可直接写，失败时统一引导「另存为」，不引入存储权限。
- provider 不支持写：只能「另存为」；UI 明确显示「当前文件不支持编辑，可另存为新文件」。

### 4.3 编码与换行保持

新增 `DocumentTextCodec`（建议接口示意，非最终代码）：

```kotlin
enum class NewlineStyle { LF, CRLF }

data class DocumentCodecMeta(
    val charsetName: String,   // UTF-8 / UTF-8-BOM / UTF-16LE / UTF-16BE / GB18030 / UTF-8-FALLBACK
    val hasBom: Boolean,
    val newline: NewlineStyle,
    val uncertain: Boolean,
)

data class DecodedText(val text: String, val meta: DocumentCodecMeta)

object DocumentTextCodec {
    fun decode(bytes: ByteArray): DecodedText
    fun encode(text: String, meta: DocumentCodecMeta): EncodeResult
}
```

规则：

| 情况 | 保存策略 |
| --- | --- |
| UTF-8 | UTF-8 无 BOM，保持原 LF / CRLF |
| UTF-8-BOM | UTF-8 + BOM，保持换行 |
| UTF-16 LE / BE | 保持编码和 BOM，保持换行 |
| GB18030 | 优先保持原编码；`CharsetEncoder` 严格编码，新增字符不可表示时弹出选择 |
| UTF-8-FALLBACK / uncertain | 禁止覆盖原文件，只允许「另存为 UTF-8」，避免把已损坏的文本写回原文件 |
| 同一文件内 LF / CRLF 混合 | 编辑器统一内部使用 `\n`；保存时按「原文档多数换行」统一写回，并在首次保存时提示一次 |

不可表示字符处理弹窗：

```
原文编码为 GB18030，新增字符无法用该编码保存。
[以 UTF-8 另存为]   [返回修改]
```

编辑上限建议：

- 阅读上限仍为 20MB；
- **一期可编辑上限建议为原始字节 ≤ 1MB**；超过则显示「文档较大，当前为阅读模式」并禁止进入编辑；
- 该上限先用 JVM + 真机基准验证，必要时调整为 512KB 或 2MB，不写死为对外承诺。

### 4.4 保存与数据安全

SAF 没有可靠的原子替换语义，因此把「不丢数据」放在首位。

**保存路径（content://）**：

1. 在内存中完成：换行标准化 → 编码 → 校验字节大小；
2. 若覆盖原文件，先把原文件当前磁盘内容 / 本次修改草稿保存到应用私有目录；
3. 优先使用 `ContentResolver.openFileDescriptor(uri, "rw")`：
   - `FileOutputStream(fd.fileDescriptor)` 写入；
   - `channel.truncate(bytes.size)` 截断多余旧内容；
   - 可用时 `flush + fd.sync()`。
4. provider 不支持 `rw` 时回退 `openOutputStream(uri, "wt")`；
5. 写入失败：保留草稿，UI 提示「保存失败，已保留草稿，可重试 / 另存为」；不自动关闭编辑页；
6. 成功：更新 `RecentStore`（`lastOpened`、名称），清理草稿和旧快照；
7. `file://`：直接 `FileOutputStream`，同样先保留草稿；
8. 成功/失败均记录日志（仅本地 AppLog，不上传）。

说明：优先「先写后用 truncate 裁尾」而不是一开始就 `wt` 截断，能降低旧文件在写一半时被完全清空的风险；但不能承诺所有第三方 provider 都支持，故草稿快照是必须的。

**另存为**：

- `ACTION_CREATE_DOCUMENT`，`text/markdown`（失败可用 `text/plain` 兜底），建议文件名 `原名.md`；
- 成功后切换当前会话 URI 到新文件，并写入 `RecentStore`；
- 「另存为」不自动删除原文件、不自动删除原最近记录。

### 4.5 草稿与恢复

- `DraftStore` 存储位置：`filesDir/editor_drafts/`，键用目标 URI 的 SHA-256；未保存的新建文档使用随机 ID。
- 内容包含：草稿正文、目标 URI、显示名、编码元数据、修改时间。
- 触发时机：编辑后停手 3 秒、`onStop`、格式操作后；只有 dirty 时才写。
- 打开编辑页时若发现草稿：
  - 草稿与原文相同：静默删除；
  - 草稿不同：弹窗「发现未保存的编辑内容」，提供「恢复 / 丢弃」；
  - 外部文件已被修改等冲突检测放 P1。
- 成功保存、用户明确放弃、清除应用数据时，草稿随之清理。
- 设置页新增「清除编辑草稿」入口，并在隐私说明中注明草稿仅存于本机应用私有目录。

### 4.6 预览实现

- 编辑页顶部切换「编辑 / 预览」，不是默认分屏。
- 预览用当前内存文本，经后台线程执行：
  `MarkdownParser().parse(text)` → `RenderPipeline().build(root)` → `ReaderAdapter.submitItems(...)`。
- 复用现有 `ReaderAdapter`、主题色板、`LinkSheetDialog`（链接仍只提供复制，不联网）。
- 文本变化后 300ms 防抖重解析；切换回编辑时取消尚未完成的解析任务。
- 图片：已保存文档沿用 `ImageResolver` 解析相对路径；尚未首次保存的「未命名.md」没有基准目录，图片占位显示「图片缺失」，首次保存后恢复。
- 搜索 / 大纲 / 阅读进度在预览中不提供，保持一期简单；后续若需要再抽共享渲染控制器。

### 4.7 主题、字体与设置

- 编辑页复用 `ThemeEngine` / `ThemeApplier`：背景、文字、光标 accent、格式栏、预览同步日 / 夜主题切换。
- 编辑区固定等宽字体（`Typeface.MONOSPACE`），一期不跟随阅读字体选项，避免破坏 Markdown 对齐。
- 二期可增加「编辑字号」和「显示语法高亮」设置，不在一期引入。
- 设置页新增「清除编辑草稿」。

### 4.8 依赖与体积

- **不新增依赖**：编辑、保存、预览、草稿均用 AndroidX 现有能力和 Kotlin 标准库实现。
- 预计 DEX / 资源增量 < 200KB；release arm64 当前约 0.9MB，6MB 目标仍有充足余量。
- 新增矢量图标：编辑、预览、保存、更多、格式工具若干；全部 VectorDrawable。

## 5. 红线、性能与非功能约束

| 项目 | 要求 | 编辑功能如何满足 |
| --- | --- | --- |
| 权限数量 | manifest `uses-permission = 0` | 读写只来自 SAF 单文件授权；不申请 `WRITE_EXTERNAL_STORAGE`、`MANAGE_EXTERNAL_STORAGE` |
| 网络流量 | 0 字节 | 不引入网络库；预览链接仍只复制不打开；CI 扫描继续拦截网络 API |
| 数据收集 | 0 | 草稿、最近记录仅在应用私有目录；无统计 / 崩溃上报 |
| APK 体积 | ≤ 6MB 目标，≤ 8MB 红线 | 预计增量 < 200KB，不超过 6MB |
| 编辑打开耗时 | ≤ 800ms（500KB 文档） | 后台加载 / 解码；不做语法高亮全量扫描 |
| 编辑滚动帧率 | ≥ 50fps（≤ 1MB 文档） | 纯 EditText；超上限禁止编辑 |
| 保存耗时 | ≤ 500ms（1MB 文档） | 内存中编码后一次写入；分块 IO |
| 崩溃率 | < 0.1% | 保存失败兜底草稿；SAF 异常全部捕获；不因 provider 异常杀进程 |
| 兼容性 | Android 8.0+ | minSdk 26，`EXTRA_INITIAL_URI` 等 API 26 可用 |

> 真机性能数据当前环境无法生成，方案评审通过后需在 benchmark 流程中补齐编辑器专项基线与设备矩阵。

## 6. 测试方案

### 6.1 JVM 单测

- `DocumentTextCodecTest`：UTF-8 / UTF-8-BOM / UTF-16LE / UTF-16BE / GB18030 解码；原编码回写；BOM 保持；LF / CRLF 保持；混合换行归一；不可表示字符返回明确错误。

- `ExternalModificationTest`（P1）：磁盘内容变化识别。

### 6.2 UI / 手工回归

| 场景 | 验收 |
| --- | --- |
| 打开只读文档 → 编辑 | 弹重新授权，选择同文件后可保存；选择取消则保持只读 |

| 覆盖保存 | 返回阅读页自动刷新；文件内容 / 编码 / 换行与预期一致 |

| 未保存离开 | 三个选项行为正确 |
| 进程被杀 / 崩溃 | 重开恢复提示，恢复后内容不丢 |

## 8. 主要风险与对策

| 风险 | 概率 / 影响 | 对策 |
| --- | --- | --- |
| SAF provider 写回能力参差 | 高 / 高 | 写前 `canWrite`，失败回退另存为；草稿兜底 |
| SAF 无原子写，中途失败损坏原文件 | 中 / 高 | 先完整内存编码；优先 `rw + truncate`；覆盖前私有快照；失败不静默 |
| `EditText` 大文档卡顿 / OOM | 中 / 高 | 一期 1MB 上限，超出只读；专项基准后再调整 |
| 编码转换不回去 | 中 / 中 | 严格编码检测；不可表示字符弹窗；uncertain 文档禁止覆盖 |
| 产品「只读」口碑与文案冲突 | 中 / 中 | 更新 PRD、README、应用商店描述；「轻编辑」明确为可选能力 |
| 预览大文档重复解析卡顿 | 中 / 中 | 300ms 防抖、后台线程、编辑上限；必要时取消旧任务 |
| 误覆盖外部修改 | 中 / 中 | 一期草稿兜底；P1 增加外部修改检测与冲突弹窗 |
| 多 provider / 不同 ROM IME 差异 | 中 / 低 | 手工矩阵覆盖 DocumentUI、SD 卡、文件管理器；IME 异常降级 |
